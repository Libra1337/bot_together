# AI 对话配置页面设计

## 目标

在现有管理后台新增独立的“AI 对话”子页面，让管理员可以修改 AI API 地址、API Key 和模型名称，检测配置是否可用，并在保存成功后立即重启 Bot 使新配置生效。

## 页面与权限

- 新增页面：`/dashboard/ai`。
- 在后台导航和控制台首页增加“AI 对话”入口。
- 页面沿用现有 Dashboard 会话认证；未登录用户跳转到登录页。
- 页面中的敏感 Key 只显示脱敏值；Key 输入框为空时表示保持当前 Key 不变。
- 保存、检测和查看当前配置均不能通过未认证的页面或接口完成。

## 配置流程

1. 页面加载时从当前 `config.yaml` 读取 `ai.base_url`、`ai.model` 和 Key 是否已配置。
2. 管理员填写或修改表单。
3. “检测连接”只使用表单值进行一次 OpenAI 兼容接口检测，不写入配置。
4. “保存并重启”会再次检测完整配置；检测失败时不修改文件。
5. 检测通过后，以临时文件写入完整 YAML，再用原子替换更新 `config.yaml`。
6. 只执行 `systemctl restart official-qqbot`，控制 API 和 Dashboard 保持在线。
7. 重启失败时恢复原始配置并再次尝试重启旧版本 Bot；页面明确显示失败原因。
8. 所有审计日志只记录 API 地址和模型，不记录 API Key。

## 后端边界

新增独立的 `control_api/ai_config.py`，负责：

- 读取并规范化当前 AI 配置。
- 校验 `http`/`https` API 地址、模型名称和 API Key。
- 调用 `{base_url}/chat/completions`，发送最小测试请求验证服务和模型可用性。
- 原子更新 YAML 并保留其他配置段。
- 执行 Bot 重启命令并检查 `official-qqbot` 是否处于 active 状态。

`control_api/app.py` 只负责认证、表单解析、页面响应、审计记录和调用该边界；不在路由中直接拼接 YAML 或执行命令。

## 页面交互

- 表单字段：API 地址、API Key、模型名。
- 状态区显示：当前配置、检测成功/失败、保存成功/失败、重启成功/失败。
- 检测按钮在请求期间禁用并显示加载状态。
- 保存按钮在请求期间禁用，只有检测通过后才写盘和重启。
- API Key 不回显完整值，错误提示不包含请求头或完整响应中的密钥。
- 页面使用现有后台的中文、蓝色按钮、轻圆角和 150-300ms 过渡效果。

## 失败处理

- 地址、模型或 Key 为空：立即提示并不发起网络请求。
- 网络超时、DNS 错误、非 2xx 响应或响应缺少有效 choices：检测失败，不保存。
- 文件写入失败：保留旧配置并提示。
- 重启命令失败或 Bot 未 active：恢复旧配置并提示；控制台服务不被重启。
- 不把外部 API 的完整响应体展示给用户，错误内容只保留状态码和短消息。

## 测试范围

- 配置读取、Key 脱敏、地址和字段校验。
- 成功检测、超时、非 2xx 和空响应处理。
- 原子保存保留非 AI 配置段，空 Key 保留旧 Key。
- 重启成功、重启失败回滚。
- 未登录不能访问 AI 页面或提交操作。
- 页面包含中文字段、检测按钮、保存按钮和脱敏 Key，不包含完整 Key。
